# BUG 修复：下单页按 URL 参数取套餐时类型不匹配，导致提交被「时段 / 小时数」校验拒绝

- 日期：2026-09-26
- 发现方式：用户真机（HBuilderX 运行）点击「提交预约」后控制台报错
- 严重级别：**阻断闭环**（除首个套餐外，其余套餐一律下不了单）
- 所属功能：feat-009 游客端-下单页（`pages/order/create.vue`）

## 一、现象

用户提交预约时，控制台出现两条报错（同一次会话内先后出现，取决于所选套餐）：

```
create.vue:379 提交预约失败 ApiError: 小时加购的小时数需在 1-12 之间
    at invalidRequest (errors.js:56:10)
    at Object.createOrder (index.js:467:13)
    at Proxy.submit (create.vue:371:24)

create.vue:379 提交预约失败 ApiError: 半天陪游必须选择上午或下午
    at invalidRequest (errors.js:56:10)
    at Object.createOrder (index.js:462:13)
    at Proxy.submit (create.vue:371:24)
```

伴随的可疑观感（同一根因，容易被人忽略）：

- 下单页「套餐」一行的名称、时长与底部「合计」金额**不是**详情页里选中的那个套餐；
- 「景点」一行显示为 `—`（景点改名后恢复正常，因为 `uni.showActionSheet` 赋的是数字 id）。

## 二、复现步骤

前置：数据层为 mock（`api/index.js` 的 `USE_MOCK = true`），已登录（任意角色）。

1. 首页选一个景点 → 进入地陪列表 → 选一位地陪进入详情（`pages/clerk/detail`）；
2. 在详情页选中一个**不是列表第一个**的套餐（例如地陪报价顺序是「市区半日 / 熊猫专项」，选「熊猫专项」）；
3. 选一个可约日期 → 点「立即预约」进入下单页（`pages/order/create`）；
4. 观察「套餐」一行：显示的是**第一个**套餐而不是刚选的那个（合计金额同样不对）；
5. 点「提交预约」→ 报错：所选套餐是小时加购时报「小时加购的小时数需在 1-12 之间」；所选套餐是半日时报「半天陪游必须选择上午或下午」。

选到列表第一个套餐时不会复现，所以容易被当成偶发。

## 三、根因

**URL 查询参数一律是字符串，而数据层返回的 id 是数字，页面用 `===` 直接比较，查找静默落空。**

链路：

```288:293:pages/clerk/detail.vue
      const url =
        `/pages/order/create?guideId=${this.guideId}` +
        `&packageSkuId=${pkg.packageSkuId}` +
        `&attractionId=${attractionId}` +
        `&appointDate=${this.selectedDate}`;
```

`pkg.packageSkuId` 是数字（`api/mock/index.js` 的 `toPackage()` 返回 `packageSkuId: pkg.id`），拼进 URL 后到 `onLoad(options)` 里变成字符串 `'3'`：

```202:210:pages/order/create.vue   （修复前）
    selectedPackage() {
      const packages = this.guide.packages || [];
      return packages.find((pkg) => pkg.packageSkuId === this.packageSkuId) || packages[0] || {};
    },

    /** 下单页控件规则：全部取自 BOOKING_TYPE_UI */
    ui() {
      return BOOKING_TYPE_UI[this.selectedPackage.bookingType] || { showTimeSlot: false, showHours: false, slotOptions: [] };
    },
```

`selectedPackage` 用 `pkg.packageSkuId === this.packageSkuId` 查找 → `3 === '3'` 为 false → `find` 返回 `undefined` → **静默回落成 `packages[0]`**。于是：

- `ui`（`BOOKING_TYPE_UI`）按**错误的套餐类型**决定控件，提交时 `payload` 里因此缺字段或多字段：

```368:369:pages/order/create.vue   （修复前）
        if (this.ui.showTimeSlot) payload.timeSlot = this.timeSlot;
        if (this.ui.showHours) payload.hours = this.hours;
```

- 接口按 `packageSkuId` 反查真实套餐类型（`api/mock/index.js` 的 `createOrder`），要求该类型必须带的字段却缺失 → 命中两条校验：

```461:468:api/mock/index.js
    if (ui.showTimeSlot && [C.TIME_SLOTS.MORNING, C.TIME_SLOTS.AFTERNOON].indexOf(timeSlot) < 0) {
      throw invalidRequest('半天陪游必须选择上午或下午', [`timeSlot=${timeSlot}`]);
    }
    const finalTimeSlot = ui.showTimeSlot ? timeSlot : C.TIME_SLOTS.NONE;
    const finalHours = ui.showHours ? Number(hours) : 0;
    if (ui.showHours && (!(finalHours >= 1) || finalHours > 12)) {
      throw invalidRequest('小时加购的小时数需在 1-12 之间', [`hours=${hours}`]);
    }
```

- 同一根因还让 `attractionName` 查找落空（显示 `—`）。

错误**不在数据层**：`byId()` 一直有 `Number(id)` 兜底，所以接口拿到字符串 id 也能查对套餐；问题只出在页面自己做的 `===` 比较。

## 四、修复方案

在参数入口（`onLoad`）把 URL 参数归一化成数字，页面内部一律用数字 id：

```184:187:pages/order/create.vue
function toId(value) {
  const id = Number(value);
  return Number.isFinite(id) && id > 0 ? id : '';
}
```

```254:257:pages/order/create.vue
    this.guideId = toId(options.guideId);
    this.packageSkuId = toId(options.packageSkuId);
    this.attractionId = toId(options.attractionId);
    this.appointDate = options.appointDate || '';
```

选择「入口归一化」而不是把每个 `===` 改成 `Number(a) === Number(b)` 的原因：

- 页面里所有 id 都是一份数据（`selectedPackage` / `attractionName` / `changeAttraction` / 提交 `payload`），逐个比较点做兜底会漏；
- `payload` 送给接口的也是数字，与未来 HTTP 版本的 JSON 约定（id 为数字）一致，不需要后端容忍字符串。

未改动 `pages/clerk/detail.vue`（URL 天然是字符串，这是平台行为）；`pages/order/create.vue` 不是 `docs/legacy-assets.json` 的在册资产（feat-009 新建），因此无需登记与刷新哈希。

## 六、回归验证结果

### 1. 针对本 bug 的动态回归（临时脚本，验证后已删除）

脚本复刻下单页逻辑（URL 参数按字符串传入），对真实 mock 数据层跑 `createOrder`：
「旧逻辑（原样字符串）」与「新逻辑（归一化）」各占一个档期，避免下单占用档期互相干扰。

```
=== 下单页参数归一化回归 ===
用例数（地陪 × 非首个套餐 × 两天档期）：33
旧逻辑：选中套餐与 URL 不一致 33/33；下单被拒 21；下成但落了错套餐 0
新逻辑：选中套餐与 URL 不一致 0/33；下单被拒 0
拒绝原因分布：
  13 × 小时加购的小时数需在 1-12 之间
  8 × 半天陪游必须选择上午或下午
```

- 旧逻辑 **33/33 全部选错套餐**，其中 21 单被接口拒回，两条报错文案与用户反馈**逐字一致**；
- 新逻辑 **0/33 选错、0 被拒**，复现与修复双向确认。
