# BUG 修复：可约档期生成恒为空，游客无法提交预约

- 日期：2026-09-26
- 严重级别：**阻断**（详情页「可约日期」永远为空 → 「立即预约」永远提示「请选择预约日期」→ 下单闭环断在第一步）
- 发现方式：`scripts/smoke-flow.mjs`（首个动态门禁，在第 1 个 bug 修完后继续暴露）
- 相关：`docx/codeimpl-sum/设计文档-feat-008-地陪详情页.md`、`设计文档-feat-009-下单页.md`、`docx/bugfix/BUG修复-20260926-mock仓库缺字典表导致运行时崩溃.md`

## 1. 现象

任意地陪的详情页都显示「近两周暂无档期，可稍后再看」，`getGuideAvailableDates()` 返回空数组；即使绕过前端直接调 `createOrder`，也会因「档期不可约」被拒。

```
可约日期不为空（否则游客无法下单）  FAIL —— 0 天可约
```

## 2. 复现步骤

1. `node scripts/smoke-flow.mjs`（或在页面里打开任意地陪详情页）
2. 观察「可约日期」区域为空 / 接口返回 `[]`

## 3. 根因

`api/mock/generate.js` 生成档期时，先按区域与套餐生成了关系行 `guidePackages`（带 `enabled: 1`），但在计算「可预约类型」时误用了**另一批对象**：

```js
// 修复前
const pickedPackages = rnd.pickMany(packageSkus, rnd.countIn(config.guidePackageCount)); // ← seed 里的套餐 SKU，没有 enabled 字段
pickedPackages.forEach((pkg) => {
  guidePackages.push({ id: relationId, guideId, packageSkuId: pkg.id, price, enabled: 1 });
});

const bookingTypes = pickedPackages
  .filter((item) => item.enabled === 1)   // ← 对 seed SKU 筛 enabled，永远筛空
  .map((item) => packageSkus.find((pkg) => pkg.id === item.packageSkuId).bookingType);
```

`pickedPackages` 是**字典表对象**（`packageSkus` 的元素），不是上面 push 进去的关系行，它们没有 `enabled` 字段 → `filter` 结果恒为空 → `uniqueBookingTypes` 为空 → 内层 `forEach` 不执行 → **50 个地陪的 `guideAvailableDates` 一行都没有**。

```js
// 修复后
const bookingTypes = pickedPackages.map((pkg) => pkg.bookingType);
```

**为什么之前没被发现**：

- `pickedPackages` 非空，所以「套餐报价」等其它数据都正常，只有档期是空的，看起来像「业务上这几天约满了」；
- `check-mock.mjs` 的规模自检只统计到「地陪 / 景点 / 订单 / 区域 / 套餐」五类，**没有统计档期表**，空表不会报错；
- 空循环还顺带掩盖了同块代码里的其它风险：循环体不执行时，任何写法错误都不会暴露。

## 4. 修复方案

1. `api/mock/generate.js`：去掉对 seed SKU 的 `enabled` 过滤（它们本来就是可售的），并在代码里写明这个坑
2. `scripts/smoke-flow.mjs`：新增断言「可约日期不为空（否则游客无法下单）」与「可约日期含所选套餐类型」，把这条链路纳入门禁
3. （未做）`check-mock.mjs` 增加档期表非空的静态断言 —— 该脚本只能读源码，做不了跨表基数判断；由动态门禁覆盖即可

## 5. 改动文件

- `api/mock/generate.js` — 修正档期生成的可售套餐口径，并补注释
- `scripts/smoke-flow.mjs` — 新增档期相关断言（第 1 个 bug 引入的门禁，本轮同时覆盖本 bug）
