# BUG 修复（含排查）：页面报 `OrderApi` undefined —— 旧模块缓存 + 数据层缺模块报错不可读

- 日期：2026-09-26
- 严重级别：**排查类**（源码自洽，运行的是旧模块）+ 两处**加固**（可读报错、版本戳与导出面门禁）
- 发现方式：用户反馈管理端「订单管理」打不开
- 相关：`api/index.js`、`scripts/smoke-flow.mjs`、`AGENTS.md`

## 1. 现象

进入后台订单管理页立即报错：

```
加载订单失败 TypeError: Cannot read properties of undefined (reading 'getAllOrders')
    at Proxy.loadList (appointment.vue:191:58)
    at Proxy.onLoad (appointment.vue:171:10)
```

即 `OrderApi` 在页面里是 `undefined`。

## 2. 复现步骤

1. 「我的」页切换为管理员 → 进入订单管理
2. 页面报上述错误（`api/index.js` 的 `OrderApi` 为 undefined）

## 3. 根因

### 3.1 源码是自洽的（逐处核对）

| 位置 | 内容 |
|---|---|
| `api/mock/index.js:419` | `export const OrderApi = { ... }` ✓ |
| `api/index.js:30` | `export const OrderApi = pickModule('OrderApi')`（当时是 `adapter.OrderApi`）✓ |
| `pages/admin/appointment.vue:191` | `await OrderApi.getAllOrders(params)` ✓ |
| `scripts/smoke-flow.mjs` | 同一份源码跑通 `createOrder / acceptOrder / confirmOrder / completeOrder / getAllOrders` → 37/37 ✓ |

### 3.2 直接原因：dev server / 浏览器仍在用旧模块

页面代码是新的（第 191 行就是新写的 `OrderApi` 调用），但 `api/index.js` 是旧的 —— 旧版本里没有 `OrderApi` 这个导出，于是 `import { OrderApi }` 拿到 `undefined`，页面调用时报出那句 cryptic 的 `Cannot read properties of undefined`。

这类"新旧混搭"在 vite dev server 上很常见，尤其这个项目还有两个放大因素：

- `api/mock/index.js` 的仓库是**模块级缓存**（`getDb()` 只计算一次），进程不重启换不干净；
- 本轮改动横跨 `api/`、`pages/`、`pages.json`，热更新很容易只换掉其中一部分。

> 这是同一个会话里**第三次**出现「报错栈与源码对不上」（前两次：`store.regionTypes` undefined、`byId` undefined）。所以本次的重点不是再修一次 bug，而是让这类问题**可自证、可自查**。

### 3.3 为什么难自查：数据层缺模块时没有可读的失败点

`export const OrderApi = adapter.OrderApi;` 在模块缺失时静默得到 `undefined`，页面调用才炸，报错里看不出"是数据层缺模块"还是"页面写错"。

## 4. 修复方案

1. **数据层加「取模块即检查」**（`api/index.js`）

   ```js
   function pickModule(name) {
     const module = adapter[name];
     if (!module) {
       throw new Error(
         `数据层缺少模块 ${name}（数据层版本 ${DATA_LAYER_VERSION}，数据源 ${USE_MOCK ? 'mock' : 'http'}）。`
         + '若刚改过 api/ 目录：停掉 dev server → 删除 node_modules/.vite 与 dist → 重启，并硬刷新浏览器。'
       );
     }
     return module;
   }
   export const OrderApi = pickModule('OrderApi');
   ```

2. **加版本戳 + 启动自报家门**

   ```js
   export const DATA_LAYER_VERSION = '2026-09-26.2';
   console.log(`[api] 数据层 ${DATA_LAYER_VERSION}｜数据源 mock｜模块 RegionApi / … / UserApi`);
   ```

   控制台没有这一行、或模块列表里没有 `OrderApi`，就说明页面加载的是旧模块 —— 一眼可判，不必再猜。

3. **门禁覆盖数据层的导出面**（`scripts/smoke-flow.mjs` 第 0 组）

   - 6 个业务模块必须都存在且为对象
   - `DATA_LAYER_VERSION` 必须存在
   - `USE_MOCK` 必须为 true

   早先的闭环校验只"调用"模块，不会报告"少了某个模块"；现在导出面本身被断言住。

4. **把处置步骤写进 `AGENTS.md`**（旧构建 / 旧模块缓存三步法），变成团队规则而不是口头经验。

## 5. 改动文件

- `api/index.js` — 新增 `pickModule()` 守卫、`DATA_LAYER_VERSION` 版本戳与启动日志（资产已登记原因并刷新哈希）
- `scripts/smoke-flow.mjs` — 新增第 0 组「数据层导出面」断言（37 → **40**）；修正「一项都没跑」时的计数显示（原来会打印 `-1/0`）
- `AGENTS.md` — 新增「改了代码但页面没生效？」排查章节
- `progress.md` / `session-handoff.md` — 记录结论与三步法

## 7. 给使用者的处置步骤（复述）

1. 停掉 dev server（Ctrl+C）—— mock 的仓库是模块级缓存，不停进程换不干净
2. 删掉 vite 缓存与产物：`Remove-Item -Recurse -Force node_modules\.vite, dist -ErrorAction SilentlyContinue`
3. 重启 `npm run dev:h5`，浏览器**硬刷新**（Ctrl+Shift+R）或换新标签页
4. 看控制台：出现 `[api] 数据层 2026-09-26.2｜…` 才算加载到新代码
