# BUG 修复：mock 数据仓库缺字典表，区域 / 景点 / 套餐接口运行时崩溃

- 日期：2026-09-26
- 严重级别：**阻断**（首页与详情页在真机/浏览器里直接报错，MVP 无法演示）
- 发现方式：新增的端到端闭环校验 `scripts/smoke-flow.mjs`（首个动态门禁）
- 相关：`docx/codeimpl-sum/设计文档-feat-004-MVP数据层.md`、`设计文档-feat-006-景点列表页.md`

## 1. 现象

页面调用任何涉及区域、景点或套餐的接口都会抛错，界面空白：

```
TypeError: Cannot read properties of undefined (reading 'filter')
    at Object.getRegionList (api/mock/index.js:259:34)
```

首页（景点列表）一进就炸；地陪详情、套餐列表、可约日期同样不可用。

## 2. 复现步骤

1. `node scripts/smoke-flow.mjs`（或任意方式调用 `RegionApi.getRegionList()`）
2. 立刻抛出上述 TypeError

浏览器/真机上表现为：首页空白、控制台报 `Cannot read properties of undefined`。

## 3. 根因

`api/mock/index.js` 的接口实现大量按 id 从仓库里查字典表：

```js
store.regionTypes.filter(...)          // getRegionList
byId(store.regionTypes, id)            // toAttraction / toGuide
byId(store.packageSkus, packageSkuId)  // toPackage / createOrder
byId(store.attractions, id)            // toGuide.attractions / createOrder 校验
```

但 `api/mock/generate.js` 的返回值里**只有 `users / guides / 关系表 / orders`**，字典表（`regionTypes` / `packageSkus` / `attractions`）只是从 `seed.json` 里读进来用作生成素材，**没有放进返回的仓库对象**。于是 `store.regionTypes` 恒为 `undefined`。

```js
// 修复前
return { seed, generatedAt, users, guides, guideRegionTypes, ... , orders, stats };

// 修复后
return {
  seed, generatedAt,
  regionTypes, packageSkus, attractions,   // ← 字典表原样带出
  users, guides, guideRegionTypes, ... , orders, stats
};
```

**为什么之前没被发现**：6 个旧门禁全部是静态的 —— `check-mock.mjs` 解析源码与 `seed.json` 做数据一致性校验，从不执行 `getDb()`，因此「仓库缺 key」这类**运行时**问题它看不见。这正是本轮新增 `smoke-flow.mjs` 的原因。

## 4. 修复方案

1. `api/mock/generate.js`：返回值补上 `regionTypes` / `packageSkus` / `attractions` 三张字典表（附注释说明为何必须带出）
2. 新增 `scripts/smoke-flow.mjs`：把 `api/` 复制到声明 `type: module` 的临时目录后真实跑三端闭环，并加 `--self-test`（故意抽掉字典表，校验必须失败）
3. `init.ps1` / `init.sh`：插入「6/7 端到端闭环校验」，构建顺延为 7/7
4. `AGENTS.md`：验证命令与完成定义加入该门禁，并说明「数据层改动必须跑动态校验」

## 5. 改动文件

- `api/mock/generate.js` — 仓库返回值补三张字典表
- `scripts/smoke-flow.mjs` — 新增端到端闭环门禁（含 `--self-test`）
- `init.ps1` / `init.sh` — 验证入口 6 步 → 7 步
- `AGENTS.md` — 验证命令、完成定义、动态校验说明
