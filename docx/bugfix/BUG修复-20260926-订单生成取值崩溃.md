# BUG 修复：mock 订单生成取值崩溃 + seed.sql 空格导致一致性校验误报

- 日期：2026-09-26
- 影响范围：`api/mock/generate.js`（订单生成）、`scripts/check-mock.mjs`（一致性校验）、`docx/database/seed.sql`（两行格式）
- 严重级别：高（数据层无法加载 → 所有页面取不到数据）
- 发现方式：`node scripts/check-mock.mjs` 运行时崩溃 + 一致性校验报错

## 现象

1. 运行 `node scripts/check-mock.mjs` 直接抛异常：

```
<anonymous_script>:288
      attractionId: attraction.id,
                               ^
TypeError: Cannot read properties of undefined (reading 'id')
    at eval (eval at loadEsmModule (.../scripts/check-mock.mjs:33:19))
    at Object.generateMockData (...)
```

2. 修掉崩溃后，一致性校验报 seed.json 与 seed.sql 不一致（景点 20 vs 19），并指出 `att-longquan-hill`、`att-night-river` 的区域归属对不上。

## 复现步骤

1. `node scripts/check-mock.mjs`（用当时版本的 `api/mock/generate.js`）
2. 观察订单生成阶段崩溃
3. 修掉崩溃后再跑，观察「景点 20 条 vs seed.sql 19 条」的不一致报错

## 根因

两个独立问题，第二个是第一个的诊断盲区造成的：

### 问题 A：订单生成对「可能为空的集合」直接取值

```js
const guide = rnd.pick(approvedGuides);
const guideAttractionIds = guideAttractions.filter((item) => item.guideId === guide.id).map((item) => item.attractionId);
const attraction = attractions.find((item) => item.id === rnd.pick(guideAttractionIds));  // ← 空集合时 undefined
...
attractionId: attraction.id,   // ← 在这里崩
```

`rnd.pick([])` 返回 `undefined`，`find` 再返回 `undefined`，随后访问 `.id` 抛错。当时没有任何保护，也没有断言去保证「已通过的地陪必然有擅长景点」。

**诊断盲区**：第一版诊断指标是

```js
approvedGuides.filter(g => !guideAttractions.some(r => r.guideId === g.id))
```

而 `approvedGuides` 本身已经被「有景点 + 有套餐」过滤过 —— 这个指标**恒为空，自我实现**，等于没有诊断能力，把真实分布掩盖了。

### 问题 B：`seed.sql` 两行逗号后缺空格

```sql
(13, 'att-longquan-hill','龙泉山城市森林公园', ...   -- 逗号后没有空格
(20, 'att-night-river',  '夜游锦江（东门码头）','锦江区', ...
```

校验脚本用 `, +'`（逗号后至少一个空格）解析，于是这两行被漏掉。SQL 里逗号后的空格没有语义，**是校验器过于脆弱**，不该由数据来迁就。

## 修复方案

1. **订单生成改为确定性选取 + 回退**：`orderableGuides[index % length]` 替代 `rnd.pick`，景点/套餐取不到时回退到集合首项，杜绝硬崩
2. **引入「可下单」概念**：`orderableGuides` = 已通过 + 有擅长景点 + 有套餐；订单只发给这类地陪
3. **断言替代崩溃**：新增不变量检查并于 `stats` 暴露诊断
   - `guidesWithoutAttractions` / `guidesWithoutRegions` / `guidesWithoutPackages`（对**全部**地陪计算，避免再出现自我实现的指标）
   - `notOrderableGuides`（已通过却不可下单的地陪，必须为空）
4. **校验器对空格不敏感**：`check-mock.mjs` 的四处解析正则由 `, +'` 改为 `,[ ]*'`
   （用 `[ ]` 而不是 `\s`，避免跨行匹配）
5. **`seed.sql` 两行格式统一**：补上逗号后的空格，保持数据文件可读

## 改动文件

| 文件 | 改动 |
|---|---|
| `api/mock/generate.js` | 订单生成改确定性选取 + 回退；新增 `orderableGuides` 与三个诊断集合；`stats` 暴露诊断 |
| `scripts/check-mock.mjs` | 四处解析正则改为对空格不敏感；新增「地陪缺少区域/景点/套餐」「不可下单地陪」四类不变量断言；自检期望同步调整 |
| `docx/database/seed.sql` | 第 13、20 行补空格，格式统一 |

## 遗留问题

- 触发问题 A 的**具体数据组合未复现**（诊断指标当时恒为空，没有留下现场）。当前用不变量断言兜底：一旦再出现「地陪缺关系数据」或「不可下单地陪」，校验会直接失败并列出 id，而不是崩在生成阶段
- 订单生成的地陪/景点选取已改为按序号轮询（`index % length`），分布比随机更均匀，但也意味着**同一状态下相邻订单倾向于不同地陪**；如果需要更贴近真实的分布，可在 feat-005 之后调整
