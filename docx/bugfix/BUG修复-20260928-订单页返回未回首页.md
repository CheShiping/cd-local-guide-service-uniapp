# BUG 修复 · 订单页返回未回首页

- 日期：2026-09-28
- 类型：交互缺陷（返回落点不符合流程语义）
- 影响页面：`pages/order/create.vue`（下单页）、`pages/appointment/my.vue`（我的订单）
- 报告人：用户走查

## 一、现象

游客提交预约后跳转到「我的订单」，这一页**没问题**；但点左上角返回键时，回到的是**地陪详情页**（即已经提交过的表单前一步），而不是首页。

用户的期望：这条流程走完（提交预约）后，返回键应当回到**首页（景点列表）**。

## 二、复现步骤

1. 以游客身份进入首页（景点列表）
2. 选一个景点 → 选一位地陪 → 进详情页
3. 选套餐 / 日期 → 点「立即预约」 → 进下单页
4. 点「提交预约」→ 提示「预约已提交」→ 自动跳到「我的订单」
5. 点左上角返回键

**修复前**：退回地陪详情页（表单已经提交过，回去没有意义）
**修复后**：回到首页（景点列表）

## 三、根因

`pages/order/create.vue` 提交成功后用 `uni.redirectTo` 打开订单页：

```js
uni.redirectTo({ url: '/pages/appointment/my' });   // 修复前
```

`redirectTo` 只替换栈顶，所以提交后的页面栈是：

```
[/pages/index/index, /pages/guide/list, /pages/clerk/detail, /pages/appointment/my]
                                                                     ↑ 栈顶
```

而订单页的 `goBack()` 是固定的 `uni.navigateBack()`：

```js
goBack() {
  uni.navigateBack();   // 修复前：永远退回栈里的上一页
}
```

于是退回了 `pages/clerk/detail`（下单页被 `redirectTo` 换掉后，栈里它的上一页就是详情页）。

根因不是「返回写错了」，而是**订单页有两个入口、返回语义却只有一套**：

| 入口 | 打开方式 | 期望的返回落点 |
|---|---|---|
| 下单页提交成功 | `redirectTo`（替换栈顶） | **首页**（这趟流程的起点） |
| 「我的」页 → 我的订单 | `navigateTo`（压栈） | **「我的」页**（上一页） |

## 四、修复方案

给订单页一条**入口标记**，返回时按标记分支 —— 只改一处判断，不额外增加跳转。

1. 下单页把入口写进 URL：

```js
// pages/order/create.vue
uni.redirectTo({ url: '/pages/appointment/my?from=create' });
```

2. 订单页 `onLoad` 记住它（路由参数一律是字符串，这里只与字面量比较，不参与任何 id 判断）：

```js
// pages/appointment/my.vue
onLoad(options) {
  this.fromCreate = !!options && options.from === 'create';
  ...
}
```

3. 返回时分支：

```js
goBack() {
  if (this.fromCreate) {
    uni.switchTab({ url: '/pages/index/index' });   // 首页是 tabBar 页，只能用 switchTab
    return;
  }
  uni.navigateBack();
}
```

`switchTab` 会关闭所有非 tabBar 页面，所以中间的地陪列表 / 详情页会被一起清掉，回到首页干净利落。

### 为什么不做「一律回首页」

「我的」页 → 我的订单 → 返回，期望回「我的」（tab 页）；一律回首页会打断这条路径。

### 为什么不改成「先回首页再打开订单页」

那需要两次跳转（`switchTab` 首页 → `navigateTo` 订单页），用户会先看到首页闪一下，且订单页自身仍然不知道入口。入口标记方案只多了一个 URL 参数。
