# BUG 修复（含排查）：后台地陪审核报 byId undefined —— 旧构建缓存 + 门禁覆盖缺口

- 日期：2026-09-26
- 严重级别：**排查类**（源码无 bug，运行的是修复前的旧构建）+ 两处**加固**
- 发现方式：用户反馈「管理员地陪审核没出来」
- 相关：`api/mock/generate.js`、`api/mock/index.js`、`scripts/smoke-flow.mjs`

## 1. 现象

进入「地陪审核」页报错，两个 Tab 都失败：

```
加载地陪列表失败 TypeError: Cannot read properties of undefined (reading 'find')
    at byId (index.js:89:15)
    at index.js:186:20        ← toGuide 里 byId(store.regionTypes, id)
    at Object.getGuideList (index.js:347)
    at Object.getPendingGuides (index.js:391)
```

## 2. 复现步骤

1. 「我的」页切换为管理员 → 进入地陪审核
2. 页面报上述错误，两个 Tab 都空

## 3. 根因

### 3.1 直接原因：**运行的是修复前的旧构建**

`index.js:186` 是 `toGuide()` 里的 `byId(store.regionTypes, id)`，说明运行时 `store.regionTypes` 是 `undefined` —— 即「mock 仓库缺字典表」这个 bug **又出现了**。而这个 bug 在本轮早些时候已经修过：

```js
// api/mock/generate.js（已修复的版本）
return {
  seed, generatedAt,
  regionTypes, packageSkus, attractions,   // ← 字典表原样带出
  users, guides, guideRegionTypes, ... , orders, stats
};
```

**源码核对结果**：`generate.js` 的三张字典表在；`api/mock/index.js` 里过渡适配层已删除、`byId` 在 186 行被 `store.regionTypes` 调用 —— 与报错栈完全对应，说明报错来自**修复前的产物**。

最可能的情形（vite / 微信开发者工具都常见）：dev server 或小程序编译产物是修复前启动/构建的，热更新只替换了 `api/mock/index.js`，而 `api/mock/generate.js`（或其模块实例）仍是旧版本 —— 于是「新 index.js + 旧 generate.js」正好复现这个 `undefined`。

### 3.2 为什么没被门禁拦住：审核链路当时没进闭环校验

`scripts/smoke-flow.mjs` 当时覆盖了下单 / 接单 / 确认 / 完成与后台列表，但**没有调用** `getPendingGuides` / `auditGuide` / `PackageApi.getPackageList` / `UserApi.getCurrentUser` —— 报错所在的这条链路恰好是盲区。

### 3.3 报错本身不可读

`byId(list, id)` 直接 `list.find(...)`，缺表时报的是 `Cannot read properties of undefined (reading 'find')`，看不出是哪张表缺了。

## 4. 修复方案

1. **确认源码正确并保留修复**：`generate.js` 继续带出 `regionTypes` / `packageSkus` / `attractions`（无需改动）
2. **加固报错**：`byId` 先判类型，缺表时抛出可操作的信息

   ```js
   if (!Array.isArray(list)) {
     throw new Error(`mock 仓库缺少字典表：byId 收到 ${typeof list}（id=${id}）。`
       + '请检查 api/mock/generate.js 的返回值——regionTypes / packageSkus / attractions 必须原样带出');
   }
   ```
3. **补齐门禁覆盖**：`smoke-flow.mjs` 新增第 7 组断言（套餐字典 / 当前身份 / 待审列表 / 待审地陪带区域与景点 / 审核通过 / 待审数量 -1 / 已通过列表包含该地陪），把报错链路纳入动态校验。断言数 28 → 36
4. **处置建议（给使用者）**：遇到与源码不符的 `undefined` 报错时，先**重启 dev server / 重新构建**再判断是不是 bug

## 5. 改动文件

- `api/mock/index.js` — `byId` 增加缺表判断与可操作报错
- `scripts/smoke-flow.mjs` — 新增管理端审核链路等 8 项断言（含自检仍有效）
- （源码本身无需改动；`generate.js` 的修复在上一轮已完成）
