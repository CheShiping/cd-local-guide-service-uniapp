# BUG 修复 · 20260926 · SCSS 变量报未定义，实为 uni.scss 注入缓存陈旧

> 归档日期：2026-09-26
> 关联功能：feat-015（动效规范与落地）
> 类型：**环境 / 构建缓存问题**，不是代码缺陷（代码侧已用编译器自证）

---

## 1. 现象

在 HBuilderX 里运行项目（`App.vue` 动了之后热编译）报：

```
[plugin:vite:css] [sass] Undefined variable.
    ╷
318 │   animation: ds-page-in $ds-dur-page $ds-ease-out backwards;
    │                         ^^^^^^^^^^^^
    ╵
  App.vue 318:25  root stylesheet
```

读起来像是「`$ds-dur-page` 没定义」。但同一个 `uni.scss` §1.8 里的其它变量（`$ds-dur-press` / `$ds-dur-fast` / `$ds-dur-base` / `$ds-dur-spin`）在同一份 `App.vue` 样式里用得好好的，编译没停在那里。

关键线索：**报错的恰好是本轮新加的那几个变量**（`$ds-dur-page`、`$ds-dur-page-leave`、`$ds-dur-slide`），而本轮之前就存在的变量全部正常。

---

## 2. 复现步骤

1. 启动一次编译（HBuilderX 运行到微信开发者工具 / 浏览器），让 Vite 把 `uni.scss` 的注入内容加载进内存
2. **不停止运行**，在 `uni.scss` 里新增一个令牌（例如 `$ds-dur-page: 320ms;`）
3. 同时在某个样式里引用它（例如 `App.vue` 的 `.is-page-in { animation: ds-page-in $ds-dur-page ... }`）
4. 触发热编译 → 报 `Undefined variable $ds-dur-page`

---

## 3. 根因

`uni.scss` 不是被页面 `@import` 的，而是 **uni-app / Vite 通过 `additionalData` 注入**到每个 `<style lang="scss">` 前面的。这带来两个后果：

1. `App.vue` 的样式模块变化时会重新编译，但**注入的那段 `uni.scss` 内容来自编译开始时的一次读取**
2. 注入内容所对应的 `uni.scss` 模块被 Vite 的 CSS 转换缓存按文件路径缓存；它不在 `App.vue` 的依赖图里，所以 `App.vue` 变了**不会**让它失效

于是出现「新 `App.vue` × 旧 `uni.scss`」的组合：新代码引用了新令牌，而注入的旧内容里没有 → `Undefined variable`。

**证据（客观、可复核）：**

1. **错误行号反推**：`App.vue 318:25`。`App.vue` 里 `.is-page-in` 在**第 171 行**，而 318 − 171 = 147 ≈ 被内联注入的 `uni.scss` 行数 —— 说明报错确实是「注入内容 + `App.vue` 样式」这份拼接源里的一行，不是 `App.vue` 自己的行。
2. **编译器自证**：用 **HBuilderX 自带的 dart-sass**（`D:\Program Files\HBuilderX\plugins\compile-dart-sass\node_modules\sass`，正是报错用的那个编译器）把「`uni.scss` 全文 + 12 个文件的样式块」逐个拼起来 `renderSync` 编译，**全部通过**：

   ```
   ok   App.vue
   ok   pages/admin/appointment.vue
   ok   pages/admin/clerk.vue
   ok   pages/appointment/my.vue
   ok   pages/clerk/detail.vue
   ok   pages/guide/list.vue
   ok   pages/guide/orders.vue
   ok   pages/index/index.vue
   ok   pages/login/login.vue
   ok   pages/order/create.vue
   ok   pages/tabbar/mine.vue
   ok   pages/webview/agreement.vue

   全部样式块编译通过（说明变量定义没问题）
   ```

   源码用同一个编译器能过 → 说明「变量没定义」这个判断不成立，问题在注入的那份内容上。
3. **产物时间戳**：`unpackage/dist/dev/mp-weixin/app.wxss` 的修改时间是 `16:28:38`，其中**不含** `is-page-in`、也**不含** `360ms`；而 Vite 缓存目录 `unpackage/dist/cache/.vite` 的时间是 `16:54:06`。即：最后一次成功编译的产物早于本轮改动，缓存却被后续那次失败编译刷新了。

---

## 4. 修复方案

**不是改代码**（代码本来就是对的），而是清掉陈旧缓存并重启编译：

```powershell
# 1. 先停止运行（HBuilderX 点「停止运行」/ CLI Ctrl+C）——不停进程换不干净
# 2. 删掉 HBuilderX 的 Vite 缓存与旧产物
Remove-Item -Recurse -Force unpackage\dist\cache, unpackage\dist\dev -ErrorAction SilentlyContinue
# 3. 重新运行（HBuilderX 运行 / npm run dev:h5），浏览器硬刷新
```

顺带把这次的判断方法固化进 `AGENTS.md` 的「旧构建 / 旧模块缓存」排查章节：

- 现象表新增一行：**`[sass] Undefined variable $ds-xxx`，而变量明明在 `uni.scss` 里有** → 注入缓存
- 清理命令补上 HBuilderX 的路径（原先只写了 CLI 的 `node_modules\.vite` / `dist`）
- 补上「想快速证明 SCSS 本身没问题」的自证方法（用 HBuilderX 自带 dart-sass 拼起来编译一次）
