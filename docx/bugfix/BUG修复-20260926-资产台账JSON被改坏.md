# BUG 修复：资产台账 JSON 被改坏 + 校验脚本报错不友好

- 日期：2026-09-26
- 影响范围：`docs/legacy-assets.json`（保真门禁的唯一事实来源）；`scripts/verify-assets.mjs` 的错误输出
- 严重级别：高（台账无法解析 → 保真门禁完全失效，`./init.ps1` 直接中断）
- 发现方式：`node scripts/verify-assets.mjs` 报 `SyntaxError`，被门禁当场拦住

## 现象

补写 `knownGaps` 的 `resolution` 字段后，门禁打印的是 Node 原始堆栈而不是可读结论：

```
SyntaxError: Expected ',' or ']' after array element in JSON at position 8015 (line 213 column 5)
    at JSON.parse (<anonymous>)
    at verifyLegacyAssets (.../scripts/verify-assets.mjs:61:25)
```

同时 `.ps1` / `.sh` 入口在「2/4 资产保真校验」这一步中断，后面的令牌校验与构建校验都不会执行。

## 复现步骤

1. 编辑 `docs/legacy-assets.json`，在 `knownGaps` 的某个对象里补字段时多写一个 `}`：

```json
      "plannedFeature": "feat-003",
      "resolution": "..."
    }          ← 原对象已有一个 }，这里又补了一个
    },
```

2. 运行 `node scripts/verify-assets.mjs`
3. 看到 `SyntaxError`（注意：因为 JSON 无法解析，**校验等于没跑**，不会误报通过，但也没有任何可操作提示）

## 根因

两层原因，第一层是操作失误，第二层是工具设计缺陷：

1. **操作失误**：用精确片段替换补字段时，`old_str` 只截到 `"plannedFeature": "feat-003"`（没包含该对象原有的闭合 `}`），而 `new_str` 里自己写了一个 `}`，于是产生重复闭合括号。共两处（gap-001、gap-002），只有第一处报错。
2. **工具缺陷**：`verify-assets.mjs` 里直接用 `JSON.parse(await readFile(...))`，异常直接冒泡成 Node 堆栈。失败信息里只有行列号，没有「哪个文件、该怎么修」，而且看不出这是"台账格式损坏"还是"资产被改动"。

## 修复方案

1. 删掉两处多余的 `}`
2. `scripts/verify-assets.mjs` 新增 `readJson(file, label)` 包装：
   - 解析失败时输出「哪个文件不是合法 JSON + 原始错误 + 常见原因（多写闭合括号 / 漏逗号）」
   - 直接 `exit 1`，语义上仍然失败，不会静默放过
   - `docs/legacy-assets.json` 与 `pages.json` 两处解析统一走这个包装

## 改动文件

| 文件 | 改动 |
|---|---|
| `docs/legacy-assets.json` | 删除 gap-001 / gap-002 各一处多余的 `}` |
| `scripts/verify-assets.mjs` | 新增 `readJson()`；`verifyLegacyAssets` 与 `verifyRoutes` 改为调用它 |
| `progress.md` | 登记本次修复与文件清单 |
| `docx/bugfix/BUG修复-20260926-资产台账JSON被改坏.md` | 本文件 |

| 标准入口 | `./init.ps1` | 四步全绿（构建按设计跳过） |

## 遗留问题

- 台账与其它 harness 文件的 JSON 语法目前只靠门禁"解析即校验"兜底；未引入 JSON Schema 校验（收益不高，暂不做）
- 编辑台账时仍建议改完立即跑一次 `node scripts/verify-assets.mjs`，把语法错误挡在提交前
