# 设计文档：分类页签自动居中 + 内容横滑切换

- 日期：2026-09-26
- 类型：交互增强（原型 01 屏 / 07 屏的可用性修补）
- 影响页面：`pages/index/index.vue`、`pages/admin/appointment.vue`、`pages/appointment/my.vue`、`pages/guide/list.vue`
- 新增文件：`utils/hscroll.js`

## 1. 背景：两个真实可见的问题

用户截图反馈两个页面的分类行：

| 现象 | 根因 |
|---|---|
| 后台筛选行里激活的「已完成」被右边缘裁掉；首页激活的「川西…」也被裁掉 | 页签行是 `scroll-view scroll-x`，激活项只会「被动可见」。`scroll-into-view` 这类能力只保证**可见**，不会把激活项带到中间 |
| 分类只能点，不能滑 | 内容区（列表）没有横向手势；参数切换必须精确点到页签 |

结论：需要「激活项自动居中」+「内容左右滑动切换」。两件事都是**行级交互**，四个页面各写一遍必然走样，所以先做共享模块。

## 2. 方案：`utils/hscroll.js` 一个行为包

```
createTabRow({ container, row, item, index, onStep })  →  { data(), methods }
  ├─ tabScrollLeft   绑给 scroll-view 的 :scroll-left
  ├─ tabTouchStart   手势起点
  ├─ onTabScroll     @scroll 里同步当前 scrollLeft
  ├─ onTabTouchStart
  ├─ onTabTouchEnd   算横滑方向，交给页面的 onStep
  └─ centerActiveTab 把激活项滚到中间
```

页面侧只加 5 行（`data` / `methods` 各 spread 一片），分类行与内容区各绑 2 个事件。四个页面共用同一份逻辑，行为一致。

纯计算单独导出，门禁可直接断言（不依赖 DOM）：

- `centerScrollLeft()`：给定容器宽、内容总宽、当前 scrollLeft、目标项在可视区内的左偏移与宽度，算出居中所需的 scrollLeft，并**夹紧**到 `[0, 内容宽 - 容器宽]`
- `swipeStep()`：横滑位移 ≥ 60px **且** 明显大于纵向位移（1.5 倍）才判定切换，返回 `1`（下一项）/ `-1`（上一项）/ `0`（不切换）

### 2.1 居中怎么算

```
目标 scrollLeft = 当前 scrollLeft + 目标项在可视区内的左偏移 − (容器宽 − 项宽) / 2
```

位置用 `boundingClientRect` 拿：容器与子项在同一坐标系，两者 `left` 相减就是子项**在可视区内**的偏移；加上当前 `scrollLeft` 得到它在内容里的位置。内容总宽用内容行（`row`）的宽度 —— **刻意不用 `scrollOffset()`**，它的实现在各端（H5 / 微信）不完全一致，而 `boundingClientRect` 是两端都稳的。

夹紧很重要：算出来的值可能为负（首项）或超出最大可滚距离（末项），不夹紧会滚到空白。

### 2.2 横滑为什么不用 `swiper`

`swiper` 能让内容跟手滑动，但代价是**每个分类都要一份独立的列表状态**：分页页码、`hasMore`、加载中、下拉刷新、空态……首页两个分类还能忍，后台跑到 5 个状态就是 5 份状态机，且这与「切分类 = 重新拉第一页」的现有数据流是两套语义。

手势方案保持**一份列表状态**：切换即换筛选条件重新加载，分页/刷新/空态全部复用现成逻辑。

```js
swipeStep({ dx, dy })   // 位移够大、且横向明显大于纵向才切换
```

用「横向位移 ≥ 1.5 × 纵向位移」做门槛，是为了不抢列表的**纵向滚动**：竖着划列表时 `dy` 远大于 `dx`，返回 0，一切照旧。

### 2.3 各页面的落地差异

| 页面 | 分类行 | 居中 | 横滑 | 说明 |
|---|---|---|---|---|
| `pages/index/index.vue` | 区域文字页签（可溢出） | ✅ | ✅ | 行 = `[全部, ...区域]`，下标 0 是「全部」 |
| `pages/admin/appointment.vue` | 日期 picker + 状态 chip（可溢出） | ✅ | ✅ | 行 = `[日期, ...状态]`，状态从下标 1 起；日期 chip 在行首，选完滚回 0 保证完整可见 |
| `pages/guide/list.vue` | 预约类型 chip + 排序 chip | ✅ | ✅ | 只有预约类型参与；排序是开关不是分类，不参与居中，也不进入横滑序列 |
| `pages/appointment/my.vue` | 四态页签（等宽，不溢出） | — | ✅ | 不需要传选择器：没有 `container` 就不做居中 |

## 3. 关键取舍

1. **收口成共享模块，而不是四个页面各写一遍**：居中算法（尤其夹紧）与横滑门槛（尤其纵向判据）是容易写错、也容易各写各的细节；页面只声明「我这一行的选择器 + 激活下标 + 切哪个方法」。
2. **`index(vm)` / `onStep(vm, step)` 用函数传参**：页面把「谁是激活项」「切到哪一项」自己决定，模块不猜业务（首页是区域、后台是状态、地陪列表是预约类型）。
3. **手势门槛直接判 `dx/dy`，不用 `touchmove` 跟手**：不需要拦截滚动、不需要 `catchtouchmove`，也不会和 `scroll-view` 的原生滚动打架。
4. **状态放在 `data` 而不是实例属性**：`tabTouchStart` 只是瞬态数据，但放进 `data` 能避开「Vue 3 对未声明实例属性告警」这类平台差异。
5. **序列到边界就停住**：横滑到第一项/最后一项不再循环，避免用户以为「滑不动 = 卡住」。
6. **顺手修的边界**：后台日期 chip 的文案会随所选日期变长（`09-26 周六`），会让整行位置变化；选完日期把该行滚回最左，保证用户刚设的筛选条件完整可见。
